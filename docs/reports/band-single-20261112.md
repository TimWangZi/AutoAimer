# 单线程 30 条带裁剪验证

> 这是 20261112 对应版本的历史验证记录。文中原始日志、画布和二进制路径位于本地 `test-results/band-single-20261112/`，不包含在源码仓库中。

日期：2026-11-12。目标板为标准 Luckfox Pico RV1103，屏幕为 GC9A01 240×240，输入为无摄像头合成帧。

新版平均 **21.64 FPS**，前后旧版基线均值 **19.93 FPS**，提升 **8.60%**。三轮没有 SPI 错误或超时，符合保留条件；新版已安装到 `/usr/bin/autoaimer` 并持续运行。

## 实现与传输量

显示仍分为 30 个条带，每条带 8 行。启动时根据现有圆屏逐行几何计算包围矩形：左边取这 8 行的最左可见像素，右边取最右可见像素。发送时只打包矩形内的 RGB565，保持高字节先发以及原有 0x2A/0x2B/0x2C 窗口指令。

| 指标 | 完整矩形旧版 | 条带裁剪新版 |
|---|---:|---:|
| 每帧像素数 | 57,600 | 46,720 |
| 每帧像素字节数 | 115,200 | 93,440 |
| 每帧总 SPI 字节数（含指令） | 115,530 | 93,770 |
| 每帧窗口数 / SPI 事务数 | 30 / 180 | 30 / 180 |
| 最大单次像素传输 | 3,840 字节 | 3,840 字节 |

总传输量减少 **18.83%**。条带允许包含少量圆外像素，全部圆内像素恰好覆盖一次。`Display`、`OutputFrame`、`VideoComposer` 接口不变，圆屏 UI、一次缩放和单帧缓冲流程不变。生产代码只修改 `src/media/display_gc9a01.h` 和 `.cpp`；测试修改 `tests/display_check.cpp`。

## ADB 对照方法与结果

顺序为旧版 → 新版 → 旧版。每轮先预热 3 秒，再测量约 30 秒，拆成三个约 10 秒区间。读取 `spi0.0/statistics/bytes_tx` 的增量，旧版除以 115,530、新版除以 93,770，再除以单调时钟测得的秒数，得到实际送屏 FPS。SPI 消息数除以 180 的结果也与字节计数结果相符；采样可能落在一帧中间，存在少量边界误差。

| 轮次 | 时长（秒） | 三个区间 FPS | 平均 FPS | 每帧耗时（ms） |
|---|---:|---|---:|---:|
| 旧版（前） | 29.999 | 19.88 / 19.91 / 19.95 | 19.913 | 50.219 |
| 新版 | 29.989 | 21.71 / 21.61 / 21.60 | 21.641 | 46.208 |
| 旧版（后） | 30.000 | 19.95 / 19.95 / 19.92 | 19.941 | 50.148 |

前后旧版 FPS 算术均值为 **19.926852**，新版为 **21.641243**，提升 **8.6034%**。按平均 FPS 的倒数计算，基线每帧 **50.1835 ms**，新版 **46.2081 ms**，减少 **3.9755 ms**。这是整帧吞吐率对应的平均耗时，没有重新拆分各阶段计时。

| 轮次 | 线程数 | 0 / 10 / 20 / 30 秒采样点 CPU MHz | SPI 错误增量 | 超时增量 |
|---|---:|---|---:|---:|
| 旧版（前） | 1 | 816 / 600 / 816 / 600 | 0 | 0 |
| 新版 | 1 | 816 / 600 / 816 / 600 | 0 | 0 |
| 旧版（后） | 1 | 816 / 816 / 600 / 600 | 0 | 0 |

governor 均为 `ondemand`，CPU 频率只在上述采样点记录，不能代表区间内全部频率。SPI 请求频率始终为 40,000,000 Hz，没有改变控制器时钟设置。全部测试进程正常退出，返回码为 0。

本结果覆盖当前无摄像头合成输入的约 30 秒运行，不代表真实相机路径、面板扫描频率或长期稳定性。减少传输字节带来了实测收益，但整帧提升没有达到传输量减少的比例。
